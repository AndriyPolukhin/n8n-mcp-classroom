# Воркфлоу як код, які розуміє ШІ

**Стек:** n8n · Cloud Dev · MCP · Connectors · **Тривалість:** ~90 хв · **Формат:** робимо разом, потім обговорюємо
**Результат:** кожен студент має робочий n8n у хмарі, тримає воркфлоу в git, відкриває n8n для ШІ через MCP і бачить, як ШІ-агент сам будує автоматизацію.

> Головна ідея заняття: **автоматизація більше не «клікаємо в UI»**. Воркфлоу — це код (git), середовище — у хмарі (Codespaces), а ШІ — повноцінний учасник, який *використовує* і *будує* автоматизації через стандартний протокол (MCP).

---

## Блок 1 · Cloud dev: n8n за 1 хвилину (20 хв)

**Мета:** нічого не встановлювати локально.

1. Відкрийте репозиторій → **Code → Codespaces → Create codespace**.
2. Поки збирається — розберіть `.devcontainer/`:
   - `docker-compose.yml` — два контейнери: `n8n` і `dev` (ваш термінал). Чому `network_mode: service:n8n`?
   - `devcontainer.json` — порт 5678, автоматичне встановлення Claude Code.
3. Вкладка **PORTS → 5678** → створіть власника n8n.
4. **Settings → n8n API** → створіть ключ → вставте в `.env`.

**Вправа:** змініть часовий пояс у `docker-compose.yml`, перезберіть контейнер (Rebuild). Що сталося з даними n8n? (Підказка: `volumes`.)

**Обговорення:**
- Чим Codespaces / devcontainer кращі за «встанови Docker і node на ноутбук»? А чим гірші (вартість, приватність)?
- Хто в команді отримує *ідентичне* середовище і чому це важливо для автоматизацій?

## Блок 2 · Воркфлоу як код (20 хв)

**Мета:** git — джерело правди, n8n — середовище виконання.

1. Відкрийте `workflows/01-webhook-ai-triage.json`. Знайдіть: тригер, агента, модель, з'єднання `ai_languageModel`.
2. Додайте OpenRouter credential в n8n, його id — в `.env` (`OPENROUTER_CREDENTIAL_ID`).
3. ```bash
   node scripts/import.mjs --activate
   node scripts/smoke.mjs
   ```
4. Надішліть свій запит:
   ```bash
   curl -s -X POST "$N8N_URL/webhook/classroom-triage" \
     -H 'Content-Type: application/json' \
     -d '{"message":"Хочу повернути гроші за курс"}'
   ```
5. Змініть щось **в UI n8n** (наприклад, додайте категорію `"career"` у system prompt) → `node scripts/export.mjs` → `git diff`.

**Вправа:** вимкніть/зламайте ключ OpenRouter і запустіть smoke-тест. Подивіться, як `onError: continueRegularOutput` + вузол `Parse JSON` повертають зрозумілу помилку замість порожньої відповіді.

**Обговорення:**
- Що дає `git diff` для воркфлоу? Code review автоматизацій — це реально?
- Чому credentials ніколи не потрапляють у репозиторій? Як `export.mjs` це гарантує?

## Блок 3 · n8n як MCP-сервер (25 хв)

**Мета:** зрозуміти MCP — «USB-C для ШІ»: один стандарт, щоб будь-який ШІ-клієнт міг користуватися вашими інструментами.

1. Відкрийте воркфлоу **02 MCP Server**. Три інструменти (`word_stats`, `make_slug`, `course_schedule`) підключені до `MCP Server Trigger`.
2. Подивіться в `scripts/smoke.mjs`, як виглядає MCP «під капотом»: `initialize` → `tools/list` → `tools/call` (звичайний JSON-RPC по HTTP).
3. Відкрийте воркфлоу **03 Chat Agent** → кнопка **Chat** → запитайте:
   - «Який план сьогоднішнього заняття?»
   - «Зроби slug для заголовка "Автоматизація з n8n та MCP"»
   - «Скільки хвилин читати цей текст: …»
   Агент **сам дізнається**, які інструменти є (через `MCP Client Tool`), і вибирає потрібний.
4. Підключіть той самий сервер до Claude Code:
   ```bash
   set -a; source .env; set +a
   claude
   > use classroom-tools to count words in: "n8n + MCP = майбутнє автоматизації"
   ```

**Вправа (пари):** додайте у воркфлоу 02 четвертий інструмент — наприклад, `vat_calc` (ПДВ 20%) або `uah_to_usd` (через HTTP Request Tool). Перевірте, що він з'явився *і* в n8n-агенті, *і* в Claude Code — без жодних змін у клієнтах.

**Обговорення:**
- Один інструмент → багато клієнтів (n8n-агент, Claude, Cursor). Чим це краще за «окремий API для кожного»?
- Сервер зараз **без авторизації**. Чим це загрожує? Увімкніть Bearer auth — що треба змінити в клієнтах?
- Які інструменти з вашої роботи / бізнесу варто віддати ШІ через MCP? Які — точно ні?

## Блок 4 · ШІ будує автоматизацію (25 хв)

**Мета:** ШІ-агент не лише *використовує*, а й *створює* воркфлоу.

1. У `.mcp.json` є другий сервер — `n8n-builder` (спільнотний [`n8n-mcp`](https://github.com/czlonkowski/n8n-mcp)): знає всі вузли n8n і вміє керувати воркфлоу через API.
2. `CLAUDE.md` — «правила гри» для агента: репозиторій — джерело правди, жодних ключів у файлах, після імпорту — перевірка.
3. Попросіть Claude Code:
   > Створи воркфлоу `Classroom · 04 Morning Digest`: щодня о 9:00 бере `course_schedule`, формує коротке повідомлення і надсилає POST на https://webhook.site/<ваш-id>. Збережи JSON у workflows/, імпортуй і перевір.
4. Відкрийте результат в n8n. Порівняйте: JSON у git ↔ полотно в UI.

**Вправа:** дайте агенту свідомо розмите завдання («зроби щось корисне для лідів»). Що він питає? Що вигадує? Де людина має залишатися в контурі (human-in-the-loop)?

**Обговорення (фінал):**
- Хто «автор» воркфлоу, який написав ШІ? Хто відповідає, якщо він зламався о 3-й ночі?
- Що змінюється в ролі автоматизатора: від «збирача вузлів» до «архітектора + рев'юера»?
- Який мінімум перевірок (smoke-тести, рев'ю диффу, sandbox-інстанс) потрібен, перш ніж ШІ-воркфлоу піде в прод?
